# Jchat 聊天交互与浮层统一设计

## 目标

在不改变现有频道、好友、私聊及消息接口的前提下，修复自己发送消息的气泡宽度和右键菜单定位问题，将聊天页恢复为 100% 铺满，并统一搜索、频道及好友相关卡片的视觉与交互。

## 范围

本次只调整聊天页及其浮层，不改变登录页、注册页和后台管理页的缩放比例，也不修改数据库结构或服务端 API。

## 页面尺寸

- 聊天页移除 `zoom`、1900px 最大宽度及居中边距限制。
- `.anatomy-shell` 使用完整视口宽度，保留组件自身必要的内边距。
- 移动端继续使用现有响应式布局。

## 消息气泡和右键操作

- `.message-content` 不再以 85% flex 宽度拉伸；文字、图片和语音内容按实际内容宽度收缩，并继续遵守最大宽度限制。
- 自己发送的消息内容右对齐，接收消息内容左对齐。
- 右键菜单锚定用户实际点击的 `.message-text`、`.message-image` 或 `.message-voice`。
- 自己发送的消息菜单优先显示在气泡左侧；接收消息菜单优先显示在气泡右侧。
- 左右空间不足时，菜单回退到气泡上方，并限制在视口边界内。
- 页面恢复 100% 后，固定定位不再受 `zoom` 坐标换算影响。

## Header 全局搜索

- 将 `#anatomyTopSearchBtn` 从按钮改为包含原生搜索输入框的搜索区域。
- 用户直接在 Header 搜索框输入，不再打开含第二个输入框的弹窗。
- 输入获得焦点或出现查询内容时，在搜索框正下方展示结果卡片。
- 结果覆盖用户可访问的全部频道及其消息；输入采用防抖，首次聚焦时加载索引。
- 点击结果后进入对应频道或定位消息，随后收起结果卡片。
- 对话区域的搜索按钮继续只搜索当前频道或当前私聊，并使用统一浮层卡片。

## 统一浮层卡片

以下卡片共享与用户资料弹窗一致的视觉表面：

- 频道详情
- 邀请成员
- 搜索当前会话
- 添加频道
- 好友中心

共享规则包括暖白半透明背景、26px 圆角、细边框、统一阴影、顶部标题栏、关闭按钮、表单控件和纵向滚动策略。锚定型卡片保留靠近触发按钮的位置，模态型好友中心保持居中。

## 好友中心

- 入口文字、标题和无障碍名称由“添加好友”改为“好友”。
- 卡片最大宽度为 560px，并限制为 `calc(100vw - 24px)`；设置 `overflow-x: hidden`。
- 内容按照以下顺序纵向排列：
  1. 已添加的好友列表
  2. 添加好友表单
  3. 好友申请列表
- 已添加好友复用 `friendsCache`，显示头像、昵称和用户名；点击条目关闭卡片并进入对应私聊。
- 添加好友保留现有两步申请流程和可选申请理由。
- 好友申请保留接受、拒绝及理由展示。
- 内容较长时只在卡片内容区产生纵向滚动，不出现横向滚动条。

## 数据流与错误处理

- 全局搜索继续读取 `/api/channels` 和 `/api/messages/:channel`。
- 好友中心继续读取 `/api/friends` 与 `/api/friends/requests`，不增加服务端接口。
- 所有网络错误沿用现有通知组件；搜索加载失败时在结果卡片中显示状态，不阻塞页面。
- 打开好友中心时使用当前缓存即时渲染，同时触发刷新以更新好友与申请状态。

## 可访问性

- Header 搜索使用原生 `input[type=search]` 和可见/隐藏标签。
- 搜索结果支持键盘焦点，Escape 收起结果区域。
- 所有卡片保留标题关联、关闭按钮、焦点管理和 44px 触控目标。
- 卡片和列表禁止横向滚动，文本允许换行或省略。

## 验证

- 静态契约测试覆盖 100% 页面、Header 原生输入、统一浮层类、好友中心结构和无横向滚动。
- 消息菜单测试覆盖发送/接收两种方向及上方回退。
- 运行 `node --check public/js/chat.js`。
- 运行聊天 UI 专项测试，并在本地服务上检查静态资源已更新。
