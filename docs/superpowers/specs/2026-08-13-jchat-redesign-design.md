# JoyChat 重新设计 · 设计文档

> 日期：2026-08-13 · 状态：待评审
> 基于现有项目 Jchat-JoyChat v2.2.0（Node.js + Socket.IO + SQLite）

## 1. 背景与目标

**现状**：Jchat-JoyChat v2.2.0 功能齐全（频道/私聊、图片/语音/表情、撤回/回复、管理后台、日志审计、在线状态，15 个自动化测试 + 安全加固）。但前端是约 20 万字节的手写 JavaScript + 9 万字节 CSS，无框架、无构建步骤，难以支撑「精致」体验与长期维护。

**目标**：以现有项目为框架，重新设计成一个**精致、通用的团队聊天产品**，体验对标优秀产品（微信 / Telegram / Slack 的水准），同时补齐团队协作能力。

**定位**：
- 私有部署（装在自己的服务器上），任何人都能注册
- 团队 / 组织内部使用（几十到几百人规模）
- 电脑 + 手机都能用

## 2. 关键决策

| 主题 | 决策 |
| --- | --- |
| 视觉 | Claude 风格：米白暖底、珊瑚橙点缀、暖黑文字、大圆角、大量留白；支持深色模式 |
| 平台 | 响应式 Web：桌面三栏 + 手机单栏 |
| 部署 | 单进程统一（代码分离、部署统一） |
| 语言/框架 | 全程 JavaScript（不引入 TypeScript）；前端 Vue 3 + Vite；后端保留 Express + Socket.IO + SQLite |
| 隐私 | 私聊端到端加密，服务器只存密文；用登录密码派生密钥 |

## 3. 总体架构

**部署形态**（不变）：单进程、单端口，`npm start` 一键启动，页面 / API / Socket.IO 统一提供；SQLite 由 Node 内置 `node:sqlite` 提供，无额外数据库/缓存依赖。

**前端**（重写）：
- Vue 3（JavaScript）+ Vite 构建
- 组件化：侧边栏、消息流、输入框、成员列表、登录/后台等
- 用 CSS 变量做「设计规范」，统一颜色/圆角/间距，深浅色一键切换
- 响应式布局 + 移动设备识别（`navigator.userAgent` + `matchMedia`）

**后端**（保留 + 整理）：
- 保留 Express + Socket.IO + SQLite 及现有安全加固、测试
- 把 77KB 的 `index.js` 拆成清晰模块（路由、实时通信、加密、日志、状态等）
- 为新增功能补对应接口

**端到端加密**（新增）：浏览器原生 WebCrypto，不依赖后端密钥。

## 4. 界面结构

**桌面（三栏）**：左「频道 / 私聊列表」｜ 中「消息流 + 输入框」｜ 右「成员列表」。

**手机（单栏）**：频道列表收进抽屉，消息流满屏，检测到移动设备自动切换。

**侧边栏可收起**：收起后只显示 `J` 品牌图标 + 搜索图标；点 `J` 图标展开；收起时展开按钮替换为搜索图标。

**在线状态点（QQ 式，头像右下角）**：
- 在线 = 绿色
- 离线 = 红色（离线自动变红）
- 隐身 = 黄色（仅自己可见，别人看到是红色/离线）
- 请勿打扰 = 红底 + 白色横杠

## 5. 功能清单

**保留**：公共/私有频道、好友私聊、图片/语音/表情、撤回/回复、JWT 会话、管理后台、日志审计、在线状态。

**新增**：
- @提及 + 消息提醒
- 搜索历史消息 + 文件分享（不止图片）
- 深色模式 + 用户头像/个人资料个性化
- 消息回应（表情回应）

**移除**：已读回执、未读角标（用户确认不要）。

## 6. 端到端加密设计

- **密钥来源**：用户登录密码，经 PBKDF2（随机盐 + 高强度迭代）派生密钥。
- **私钥存储**：首次登录生成密钥对，私钥用派生密钥加密后存服务器；服务器只存「密码哈希」和「加密后的私钥备份」，从不见密码、也不见派生密钥，因此解不开私聊。
- **多设备**：任意设备登录输入密码 → 派生密钥 → 解开私钥 → 恢复历史（登录即恢复，无需扫码授权）。
- **私聊消息**：双方公钥 ECDH 密钥协商，消息 AES-256-GCM 加密，服务器只存密文。
- **群聊 / 频道**：不加密（保持服务器可管理、可搜索、可审计）。
- **改密码**：旧密码解密、新密码重锁，历史不丢。
- **代价（需知晓）**：密码强度 = 私聊隐私强度；密码被猜到/泄露，私聊可能被解。这是「登录即恢复」的取舍。
